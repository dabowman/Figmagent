# Fix: [BUG-050] `edit` silently no-ops when a per-node font binding is shadowed by the node's `textStyleId`

**Pattern**: boundary-guard
**Priority**: P1
**Estimated savings**: ~8 calls per occurrence, plus a class of silently-wrong output

## Background

A TEXT node with a `textStyleId` inherits the style's `boundVariables`. Binding the same field per-node does not replace them — Figma **stacks** them and the style's entry wins. Session 64 evidence on node `42:112` (style `S:8c432bbff5c9b9c23a6ffdd2fd31ff3c46e67a14,`):

- `edit({nodes:[{nodeId:"42:112", variables:{fontSize:"VariableID:2:559", lineHeight:"VariableID:321:4"}}]})` → `{"success":true,"nodesEdited":1,"totalNodes":1}`, no warnings.
- Read-back: `boundVariables.fontSize === [{2:506}, {2:559}]`, `fontSize` still resolves to the style's value.
- `setBoundVariable('fontSize', null)` removes one entry, leaving `[{2:506}]` — confirming a stack.

`src/figma_plugin/src/commands/apply.js` references `textStyleId` at `:1118` (applying a style) and `:493` (rejecting one on a non-TEXT node), but never checks an **existing** `textStyleId` against an incoming binding. `bindVariableToNode` returns no warning, so `stdlib.js:58-65`'s throw-on-warning path and `edit`'s warning collector both see nothing.

## Changes

### File: `src/figma_plugin/src/commands/apply.js`

- In `bindVariableToNode`, before performing the bind: if the target is a TEXT node, `prop(node, "textStyleId")` is a non-empty string, and the field is one a text style owns — `fontSize`, `lineHeight`, `letterSpacing`, `textCase`, `textDecoration`, `fontFamily`, `fontWeight`, `fontStyle` — return the existing structured warning shape:

  ```js
  {
    message:
      'Binding "' + field + '" on ' + node.id + ' has no effect: the node is on text style "' +
      styleName + '" (' + styleId + '), whose own binding for "' + field + '" takes precedence.',
    fix:
      'move the binding onto the style with update_styles, or detach the style first ' +
      '(edit the node without textStyleId) and then bind per-node',
  }
  ```

  Resolve `styleName` via `figma.getStyleByIdAsync(styleId)` inside the existing async path; fall back to the raw id if the lookup returns null.

- Keep the existing semantics split: the `edit`/`apply` batch path **collects** the warning and continues (so a batch is not aborted), while `stdlib.js`'s `fig.bindVariable` throws it — that wiring already exists and needs no change.

- Only the fields a text style actually owns should warn. Do **not** warn for `fill`/`stroke`/`opacity`/corner radius — a text style does not own those, and paints on a styled TEXT node bind normally (session 64's `fills` binding on the same node was live and correct).

### File: `src/figmagent_mcp/tools/apply.ts`

- Add one line to the `variables` field description: *"On a TEXT node carrying a `textStyleId`, the style's own bindings win — a per-node `fontSize`/`lineHeight`/`letterSpacing` binding is inert. Bind on the style with `update_styles`, or detach the style first."*
