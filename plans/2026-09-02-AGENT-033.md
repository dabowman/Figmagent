# Fix: [AGENT-033] `run_script` description states what `clone()` and `figma.currentPage` do on the remote transport

**Pattern**: `description-only`
**Priority**: P1
**Estimated savings**: ~3 calls per occurrence, and a class of silently misplaced nodes
**Issue**: https://github.com/dabowman/Figmagent/issues/165 — decision comment of 2026-09-02 (also carries the `run_script` sentence from BUG-047 #186's decision)

## Changes

### File: `src/figmagent_mcp/tools/script.ts` — the `run_script` description, under `Conventions:`

Add two bullets after the atomic-rollback bullet:

```
- Page context: figma.currentPage is whatever page the file was last on, does NOT persist between run_script calls, and on the remote transport is shared with every other connected process. Set it with await figma.setCurrentPageAsync(page) in every script that relies on it, and pass an explicit parent to every appendChild/createX.
- A raw node.clone() parents the clone to figma.currentPage, not to the source's parent — on remote that is usually the wrong page. Prefer write({ fromNodeId, parentId }) (it parents to the source's parent by default), or appendChild the clone to an explicit parent on the very next line.
```
