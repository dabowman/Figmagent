# Fix: [TOOL-060] `run_script` never says TEXT-node `boundVariables` are arrays

**Pattern**: description-only
**Priority**: P2
**Estimated savings**: ~4 calls per font-park script, and a binding loss nothing reports

## Background

On a TEXT node every `node.boundVariables` field (`fontFamily`, `fontSize`, `fontWeight`, `fills`, …) is an array of variable aliases, one per text segment. A script that reads a binding back and treats it as one alias either passes the array to `setBoundVariable` (Figma throws `invalid variable id`) or reads `.id` off the array (`undefined`) and skips the rebind — after it has already unbound the field. Session 65 hit both (#127, #128); the second reported success and dropped the source label's `fontFamily` binding.

The first-class route already works: `fig.bindVariable(node, field, variableId)` takes an id string and handles text fields (`bindVariableToNode`, `src/figma_plugin/src/commands/apply.js:219`). The `run_script` description lists it but never mentions the array shape.

## Changes

### File: `src/figmagent_mcp/tools/script.ts`

- Line 152: `ALWAYS await it: it returns a Promise and the guard throws inside it, so an un-awaited call swallows the rejection and the no-op masquerades as success.` → `ALWAYS await it: it returns a Promise and the guard throws inside it, so an un-awaited call swallows the rejection and the no-op masquerades as success. On TEXT nodes every node.boundVariables field (fontFamily, fontSize, fontWeight, fills, ...) is an ARRAY of aliases, one per text segment: read aliases[0].id (.id on the array is undefined) and rebind with await fig.bindVariable(node, field, thatId). Raw node.setBoundVariable takes a Variable (figma.variables.getVariableByIdAsync(id)); an alias object or the array throws "invalid variable id".`

The replacement stays inside the existing template literal; it adds no backtick and no `${`.
