# Fix: [TOOL-022] Normalize hyphenated node IDs (Figma URL form) to colon form

**Pattern**: `type-coercion` (string normalization at the Zod schema boundary)
**Priority**: P2
**Estimated savings**: ~1 call per session whenever a node ID is lifted from a Figma URL
**Sessions affected**: 38, 44, 51 (3 sessions, 2 repos, unchanged shape each time)

## Problem

Figma deep-link URLs encode node IDs with a **hyphen** (`?node-id=43-14`); the Plugin/MCP
API expects the **colon** form (`43:14`). An agent that copies an ID out of a URL the user
pasted gets a one-round-trip failure:

```
#4  read({nodeId: "43-14"})  ->  Error reading nodes: Error: Node not found: 43-14
#8  read({nodeId: "43:14"})  ->  success
```

Two calls earlier in that same session, `use_file` accepted the **full hyphenated URL**
verbatim — so within one session the same ID format is tolerated by one tool and rejected
by the next.

The error also states no fix, contrary to the project's `fail(message, fix)` rule.

## Design

Add one exported helper and apply it via `.transform()` at every schema that accepts a node
ID. Transform (not `refine`) so the normalized value is what reaches the wire command — no
handler bodies change.

Only normalize an ID that is **unambiguously** the URL form: `^\d+-\d+$`. Leave everything
else untouched — in particular do **not** touch instance-descendant IDs (`I103:1135;66:19`),
which already contain colons and semicolons, or the `0:0` document scope sentinel.

## Changes

### File: `src/figmagent_mcp/utils.ts`

Add near the other exported helpers:

```ts
/**
 * Figma deep-link URLs encode node IDs with a hyphen (`?node-id=43-14`) while the
 * Plugin API expects a colon (`43:14`). Agents routinely copy the URL form, which
 * fails with a bare "Node not found". Normalize only the unambiguous URL shape —
 * instance-descendant IDs (`I103:1135;66:19`) and every other form pass through.
 */
export function normalizeNodeId(id: string): string {
  return /^\d+-\d+$/.test(id) ? id.replace("-", ":") : id;
}

/** Zod-friendly wrapper for `nodeIds` arrays. */
export function normalizeNodeIds(ids: string[]): string[] {
  return ids.map(normalizeNodeId);
}
```

### Secondary: make the miss self-explaining

Even with normalization, an ID can be wrong for other reasons. In the plugin's node-lookup
failure path (`src/figma_plugin/src/helpers.js`, the `fail(message, fix)` helper's callers
for "Node not found"), extend the fix text:

```
fail(
  `Node not found: ${id}`,
  "Node IDs use a colon (`43:14`); Figma URLs use a hyphen (`?node-id=43-14`). " +
  "If this ID came from a URL, convert the hyphen to a colon. If it is already colon-form, " +
  "the node may live in a different file than the one selected — confirm with use_file."
)
```

## Notes

- Scope is input parsing only — no handler, wire-protocol, or plugin command changes, so
  both transports pick it up for free.
- The tracker previously left this un-planned because it "touches multiple tool handlers'
  input parsing". The `.transform()` approach keeps every handler body untouched, which
  removes that objection; the change is mechanical and individually reviewable per line.
