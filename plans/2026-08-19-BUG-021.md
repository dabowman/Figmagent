# Fix: [BUG-021] `grep` rejects scalar `type`/`componentId` with a raw Zod dump

**Pattern**: type-coercion
**Priority**: P2
**Estimated savings**: ~2 calls per search-driven session

## Problem

`grep`'s four array-valued search criteria are declared `z.array(z.string()).optional()`.
An agent that passes a single value as a bare string — the natural shape, and the shape
every scalar param in the tool takes — gets a raw MCP protocol error with no stated fix:

```
MCP error -32602: Input validation error: Invalid arguments for tool grep: [
  { "code": "invalid_type", "expected": "array", "received": "string", "path": ["type"], … }
]
```

Session 40 (call 10) hit this with `type: "COMPONENT"` and burned a round-trip retrying as
`type: ["COMPONENT"]`. This is the array-valued sibling of [TOOL-006] / [BUG-005], which
covered scalar numeric coercion.

## Fix

Accept a bare string (and a comma-separated string) for each array criterion, normalizing
to `string[]` before the handler sees it. `.optional()` short-circuits `undefined`, so no
empty-array artifacts are introduced; an already-correct `string[]` passes through the
union's first arm untouched.

Define once near the top of the file:

```ts
// Agents naturally pass a single criterion as a bare string ("COMPONENT") rather than
// an array. Accept both, plus the comma-separated form, and normalize to string[].
const stringArray = z
  .array(z.string())
  .or(z.string().transform((s) => s.split(",").map((v) => v.trim()).filter(Boolean)));
```

## Changes

### File: `src/figmagent_mcp/tools/find.ts`

Replace `z.array(z.string())` with `stringArray` on the four search criteria (leaving each
`.optional()` and `.describe(...)` chain intact):

- `componentId` — "Find instances of these component or component_set IDs"
- `variableId` — "Find nodes with direct variable bindings to these variable IDs"
- `styleId`
- `type`

Also amend the no-criterion error (find.ts:121) to name unrecognized keys rather than only
listing the valid ones, so a wrong-param call (Session 40 call 9 passed `pattern`,
`searchIn`, `nodeTypes` — all invented) reads as "wrong names" instead of "too few":

```
Error: no search criterion recognized. Valid criteria: componentId, variableId, styleId,
text, name, type, annotation, hasAnnotation. (Note: `pattern`/`searchIn`/`nodeTypes` are
not parameters of this tool — use `name` or `text` for regex matching.)
```
