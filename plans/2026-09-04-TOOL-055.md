# Fix: [TOOL-055] `component_properties` — batch across components, not just within one

**Pattern**: `missing-batch-tool`
**Priority**: P1
**Estimated savings**: ~30 calls on a library-wide property pass; ~8-10 on any multi-component property change

> `missing-batch-tool` plans are **never auto-dispatched** (`/dispatch-fixes` excludes the pattern).
> This is a specification for `/add-mcp-tool` or a hand-written PR.

## Problem

`component_properties` takes `{ nodeId, operations[] }`. `operations` batches *within* one component;
`componentProperties` (`src/figma_plugin/src/commands/components.js:398-402`) rejects anything that is
not a single COMPONENT/COMPONENT_SET. Every sibling write tool already batches across nodes — `edit`
takes `nodes[]`, `write` takes multiple roots, `create_variables`/`create_styles`/`update_variables`
take arrays, `import_library_components` takes multiple keys. This is the only write surface that
does not.

Session 63's entire task was one operation — `{ action: "add", name: "Focus", type: "BOOLEAN",
defaultValue: false, targetNodeId: <ring> }` — against **34 component sets**. The tool was used zero
times: 34 sets is 34 calls before the per-variant `bind` ops. The work went through `run_script`
instead, in 3 calls, hand-rolling the node loop the tool does not offer.

## Proposed shape

Add an optional `targets` array alongside today's single-node form. Both forms stay valid; `targets`
is a pure addition.

```jsonc
{
  "targets": [
    { "nodeId": "42:494", "operations": [
        { "action": "add", "name": "Focus", "type": "BOOLEAN", "defaultValue": false, "targetNodeId": "42:115" }
    ]},
    { "nodeId": "41:26", "operations": [
        { "action": "add", "name": "Focus", "type": "BOOLEAN", "defaultValue": false, "targetNodeId": "41:88" }
    ]}
  ]
}
```

Response — per target, in request order, so a caller can zip results back to inputs:

```jsonc
{
  "batch": true,
  "success": 33,
  "failed": 1,
  "targets": [
    { "nodeId": "42:494", "name": "Button", "results": [ /* today's per-operation results */ ],
      "componentPropertyDefinitions": { /* … */ } },
    { "nodeId": "41:26", "error": "Node must be a COMPONENT or COMPONENT_SET, got: FRAME" }
  ]
}
```

## Changes

### File: `src/figmagent_mcp/tools/components.ts`

- Schema: add `targets: z.array(z.object({ nodeId: nodeIdParam(), operations: <existing operations schema> })).min(1).optional()`, and make `nodeId`/`operations` optional. Reject "both forms" and "neither form" at the boundary with a stated fix, the way `screenshot` does for `nodeId` vs `nodeIds` (`tools/export.ts:136-152`).
- Factor the operations schema into a named const so single and batch forms share one definition.
- Send `component_properties` with `{ targets }` when batching; keep sending `{ nodeId, operations }` otherwise. The wire command name does **not** change (CLAUDE.md: wire protocol names are stable).
- Set `is_error: true` only when **every** target failed — a partial batch stays `is_error: false` and the caller inspects the per-target `error` fields, matching `edit`/`write`.
- Description: document `targets`, the per-target error isolation, and that a mixed batch reports failures inline.

### File: `src/figma_plugin/src/commands/components.js`

- `componentProperties(params)`: when `params.targets` is a non-empty array, loop it, run today's single-node body per target inside `try/catch`, and collect `{ nodeId, name, results, componentPropertyDefinitions }` or `{ nodeId, error }`. Extract the existing single-node body into a helper (e.g. `applyComponentPropertyOps(node, operations)`) so both paths run identical code.
- Keep the existing single-node return shape byte-for-byte when `targets` is absent.
- Validate `targets` with `fail(message, fix)` — empty array, non-array, and a target missing `nodeId` each need a stated fix.
- Guard the batch size the way `export.ts` does (`EXPORT_MAX_NODES`); ~50 targets is a reasonable ceiling given the remote transport's `SCRIPT_CHAR_BUDGET` (`remote/executor.ts`) — an oversized batch must fail naming the cap and the split, not silently truncate.

### File: `src/figma_plugin/src/registry/components.js`

No new command name. Confirm the existing `component_properties` entry's `lock` is still right for a
multi-node write — a batch touching many components should take the `global` lock, not a per-`nodeId`
lock keyed to one node.

### Interaction with [BUG-048]

Land [BUG-048]'s assert-and-repair **first**, inside the extracted per-node helper. Batching without
it multiplies the silent default flip by the batch size.
