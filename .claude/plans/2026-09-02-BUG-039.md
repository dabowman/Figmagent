# Fix: [BUG-039] `setProperties` names font absence when that is the cause, not a property-type problem

**Pattern**: `boundary-guard`
**Priority**: P2 — not auto-dispatched at P2 for this pattern; the plan is for a person or for re-prioritisation
**Estimated savings**: ~3 calls per session that sets text properties on instances of custom-font components
**Issue**: https://github.com/dabowman/Figmagent/issues/167 — decision comment of 2026-09-02. Routing into park-and-restore is BUG-033 (#145); this plan only fixes the stated cause.

## Problem

`src/figma_plugin/src/commands/apply.js` wraps `node.setProperties(resolved)` in a catch that appends one fix string — "verify each value matches its property type …" — to every failure. When Figma's own message says `Unable to update this text property because the component uses a font that isn't available`, that fix sends the agent to audit property types (2–3 calls to disprove).

## Changes

### File: `src/figma_plugin/src/commands/apply.js` — the `try { node.setProperties(resolved); } catch (e) {...}` block

```js
  try {
    node.setProperties(resolved);
  } catch (e) {
    const msg = e && e.message ? e.message : String(e);
    // BUG-039 — Figma names the real cause; do not paper over it with the
    // property-type remedy.
    if (/font.*(isn't|is not|not) available|unloaded font/i.test(msg)) {
      fail(
        "setProperties failed on instance " + node.id + ": " + msg,
        "the main component's TEXT is on a font this VM cannot load — park the main component's TEXT nodes on an available face ('Inter'/'Regular'), set the properties, then re-bind the fontFamily variable last; on the plugin transport install the font",
      );
    }
    fail(
      "setProperties failed on instance " + node.id + ": " + msg,
      "verify each value matches its property type — VARIANT options must be exact, INSTANCE_SWAP needs a valid COMPONENT id; read the instance to list valid keys and options",
    );
  }
```

### File: `tests/edit-direct-value-fields.test.ts` (or the test file that already exercises `componentProperties` on `apply`)

Add a case: an INSTANCE mock whose `setProperties` throws `new Error("in setProperties: Unable to update this text property because the component uses a font that isn't available.")`. Assert the per-node failure text contains `park` and `fontFamily` and does not contain `VARIANT options`. Add the control: a throw with any other message still produces the property-type fix.
