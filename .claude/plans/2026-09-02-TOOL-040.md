# Fix: [TOOL-040] `fig.createNode` returns the created tree, and a `nodeIds` list with nulls warns instead of skipping checks silently

**Pattern**: `boundary-guard`
**Priority**: P1
**Estimated savings**: ~3 calls per script-heavy session; restores post-write assertions that are skipped in silence
**Issue**: https://github.com/dabowman/Figmagent/issues/168 — decision comment of 2026-09-02

## Problem

`fig.createNode` (`src/figma_plugin/src/remote_entries/stdlib.js`) returns `create()`'s response `{ success, totalNodesCreated, tree }`, so `n.id` is undefined and `n.children` is missing. Scripts that collect ids from it hand `[null, null, null]` to the write postlude, which runs `fig.check` inside a bare `try {} catch {}` — no assertions, no message. Session 55 lost three calls and one atomic rollback to it.

## Changes

### File: `src/figma_plugin/src/remote_entries/stdlib.js`

```js
  // The full `write` tree builder (two-pass FILL sizing, font loading,
  // no default fills). spec = the same node tree `write` accepts.
  // Resolves to the created tree { id, name, type, children } — the thing a
  // script chains from (TOOL-040); the create() envelope is not useful here.
  // create()'s own warnings (font_fallback, fill_not_applied, mini-lint) are not
  // recoverable post-hoc, so carry them onto the tree rather than dropping them.
  createNode: (spec, parentId) =>
    create({ tree: spec, parentId: parentId }).then((r) => {
      if (!r || !r.tree) return r;
      if (r.warnings && r.warnings.length > 0) r.tree.warnings = r.warnings;
      return r.tree;
    }),
```

**This is a breaking change to a public `fig.*` return contract**, not a pure guard: any existing
script reading `r.success` / `r.totalNodesCreated` / `r.tree` off `fig.createNode` gets `undefined`
after it. That is the intent (the envelope is what caused TOOL-040), but call it out in the PR body
so a reviewer sees it — it is why this plan needs the `boundary-guard` gate's named test, and why it
should not be lumped with a mechanical one-liner.

### File: `src/figmagent_mcp/tools/script.ts` — `assembleRunScript`, the `mode === "write"` postlude

Replace **only** the three lines from `"if (globalThis.fig && ..."` through the closing `"}"`.
Leave `"let __warnings = [];"` (the line above them) exactly as it is — re-emitting it puts two
`let __warnings` declarations in one script scope and every write-mode `run_script` then dies with
`SyntaxError: Identifier '__warnings' has already been declared` before its first statement.

```ts
      // "let __warnings = [];" already precedes this block — do not repeat it.
      "if (globalThis.fig && __result && typeof __result === 'object' && Array.isArray(__result.nodeIds)) {",
      "  const __ids = __result.nodeIds.filter((id) => typeof id === 'string' && id.length > 0);",
      "  const __bad = __result.nodeIds.length - __ids.length;",
      "  if (__bad > 0) __warnings.push({ check: 'invalid_node_ids', message: 'nodeIds contained ' + __bad + ' null/undefined entries — post-write checks skipped for them. Fix: return the ids of the nodes you created (fig.createNode resolves to the created tree; use .id), not the create() envelope.' });",
      "  try { const __w = await globalThis.fig.check(__ids); for (const w of __w) __warnings.push(w); } catch (_e) {}",
      "}",
```

And in the tool description, change the `fig.createNode` line to: `- fig.createNode(spec, parentId) — the full write tree builder (two-pass FILL sizing, font loading, no default fills); resolves to the created tree { id, name, type, children }`.

### File: `tests/run-script.test.ts`

**Two existing assertions pin the line this plan replaces and must be updated in the same change**
— `tests/run-script.test.ts:225` and `:310` both assert
`expect(script).toContain("__warnings = await globalThis.fig.check(__result.nodeIds);")`. Change
both to the new `globalThis.fig.check(__ids)` form. Line 221's sample script also reads
`r.tree.id` off `fig.createNode`; update it to `r.id` to match the new return contract. Check
that `:329`'s `expect(script.length).toBeLessThan(1000)` still holds with the added message.

Add: `assembleRunScript("return { nodeIds: [null] }", "write")` output contains `invalid_node_ids` and `filter((id) => typeof id === 'string'`. (Existing assemble tests show the pattern.) For the stdlib half add to `tests/stdlib.test.ts` (create it if the worktree's `origin/main` base predates it): with `figma` mocked so that `create` cannot run, assert `typeof fig.createNode === "function"` and, by monkey-patching nothing else, that the wrapper resolves an object with a `tree` to that `tree` — expose the unwrap as a tiny pure helper if needed to keep the test honest.
