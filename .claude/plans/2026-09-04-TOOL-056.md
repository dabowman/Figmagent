# Fix: [TOOL-056] FSGN omits `layoutSizingHorizontal`/`layoutSizingVertical` and min/max sizing

**Pattern**: description-only (additive serializer fields — no behaviour change to existing output)
**Priority**: P1
**Estimated savings**: ~5 diagnostic `run_script` calls per session on auto-layout-heavy files

## Background

`layoutSizingHorizontal`, `layoutSizingVertical`, `layoutGrow`, `layoutAlign`, `minWidth`, `maxWidth`, `minHeight` and `maxHeight` appear **nowhere** in `src/figma_plugin/src/commands/document.js`. The serializer emits `primaryAxisSizingMode`/`counterAxisSizingMode` (`:237-240`) — the frame's mode for *its own* children — but never the node's HUG/FILL/FIXED **within its parent**.

The entire `write`/`edit` API and all CLAUDE.md layout guidance is written in `layoutSizingHorizontal: "FILL" | "HUG" | "FIXED"` terms. An agent can set it and cannot read it back, so it cannot verify its own write or diagnose a balloon frame without `run_script`. Session 64 dumped these fields by hand in five separate scripts (#23, #25, #41, #52, #53).

## Changes

### File: `src/figma_plugin/src/commands/document.js`

- In the layout block (beside the existing `paddingTop` handling at `:251-252` and the axis sizing modes at `:237-240`), add, each emitted only when defined:

  ```js
  const layoutSizingHorizontal = prop(n, "layoutSizingHorizontal");
  if (layoutSizingHorizontal) out.layoutSizingHorizontal = layoutSizingHorizontal;
  const layoutSizingVertical = prop(n, "layoutSizingVertical");
  if (layoutSizingVertical) out.layoutSizingVertical = layoutSizingVertical;
  const minWidth = prop(n, "minWidth");
  if (minWidth !== null && minWidth !== undefined) out.minWidth = minWidth;
  const maxWidth = prop(n, "maxWidth");
  if (maxWidth !== null && maxWidth !== undefined) out.maxWidth = maxWidth;
  const minHeight = prop(n, "minHeight");
  if (minHeight !== null && minHeight !== undefined) out.minHeight = minHeight;
  const maxHeight = prop(n, "maxHeight");
  if (maxHeight !== null && maxHeight !== undefined) out.maxHeight = maxHeight;
  ```

  Use `prop()` throughout — these are duck-typed reads at a serializer boundary and the remote VM throws on missing properties (`min/maxWidth` are absent on non-auto-layout-participating nodes, and `layoutSizing*` throws on a node whose parent has no auto layout).

- Gate on the same `detail` level as the existing padding/spacing family (`layout` and `full`, not `structure`) so `structure`'s ~5 tokens/node budget is unchanged.

### File: `src/figmagent_mcp/tools/document.ts`

- Update the `read` description's FSGN field summary to name the new fields, so agents know sizing is now readable.

### File: `CLAUDE.md`

- In the **FSGN format** bullet, note that `read` now reports `layoutSizingHorizontal`/`layoutSizingVertical` and min/max sizing at `detail="layout"` and above — closing the "writable but not readable" gap.
