# Fix: [BUG-040] Name the missing font as the cause of a width-0 TEXT node, and correct the documented repair

**Pattern**: `assertion` (plus `description-only` for the docs half)
**Priority**: P1
**Estimated savings**: ~19 calls per custom-font session
**Issue**: https://github.com/dabowman/Figmagent/issues/172 — decision comment of 2026-09-02

## Problem

A TEXT node whose font the remote VM cannot load (`hasMissingFont: true`) measures at width 0, and every sizing op from there is a silent no-op. Today `checkNodes` reports it as a generic `zero_width_text`, naming neither the font nor the working repair. The documented repair (`textAutoResize: HEIGHT` first) *throws* on a missing-font node.

## Changes

### File: `src/figma_plugin/src/assertions.js`

Add a pure checker next to `isNearZeroWidthText` (around line 24):

```js
// A TEXT node on a font this VM cannot load has no metrics: it measures 0 and
// every HUG/FILL from there is a silent no-op (BUG-040). Name the font and the
// repair — the generic zero_width_text message sends agents to a fix that throws.
export function checkMissingFontWidth(node) {
  if (!node || prop(node, "type") !== "TEXT") return null;
  if (prop(node, "hasMissingFont") !== true) return null;
  const w = prop(node, "width");
  if (typeof w !== "number" || w >= 2) return null;
  const fn = prop(node, "fontName");
  const face = fn && typeof fn === "object" ? fn.family + " " + fn.style : "its font";
  return {
    nodeId: node.id,
    check: "width_collapse",
    message:
      "TEXT " + node.id + " measures " + w + "px wide because " + face +
      " is not available in this VM — it has no metrics, so HUG/FILL sizing is a no-op from here. " +
      "Fix: park the node on an available face ('Inter'/'Regular', or 'Noto Sans New Tai Lue'/'Semibold' for a Semibold face — not SF Pro), " +
      "do the write, re-bind the fontFamily variable last, then resize() explicitly. textAutoResize: 'HEIGHT' throws on a missing-font node.",
  };
}
```

In `checkNodes` (around line 237), before the `zero_width_text` push: call `checkMissingFontWidth(node)`; if it returns a warning, push that and `continue` past the generic one. Nothing else changes — `checkNodes` is shared by `write`, `edit` and `run_script`'s `fig.check`, so all three surfaces get it.

### File: `tests/assertions.test.ts`

```ts
describe("[BUG-040] checkMissingFontWidth", () => {
  test("a width-0 TEXT on a missing font names the font and the resize() repair", () => {
    const node = { id: "1:1", type: "TEXT", width: 0, height: 16, hasMissingFont: true, fontName: { family: "PP Neue Montreal", style: "Semibold" } };
    const w = checkMissingFontWidth(node);
    expect(w?.check).toBe("width_collapse");
    expect(w?.message).toContain("PP Neue Montreal Semibold");
    expect(w?.message).toContain("resize()");
    expect(w?.message).toContain("Fix:");
  });
  test("a width-0 TEXT on a loaded font is not this warning (the generic zero_width_text still covers it)", () => {
    expect(checkMissingFontWidth({ id: "1:1", type: "TEXT", width: 0, hasMissingFont: false })).toBeNull();
  });
  test("a measurable TEXT on a missing font is fine", () => {
    expect(checkMissingFontWidth({ id: "1:1", type: "TEXT", width: 298, hasMissingFont: true })).toBeNull();
  });
});
```
